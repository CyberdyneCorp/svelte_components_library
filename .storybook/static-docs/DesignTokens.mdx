# Design Tokens

Design tokens are the foundational values that define the visual language of the Cyberdyne Design System. They ensure consistency across all components and products.

## Architecture

We use a **3-layer token architecture**:

```
Layer 1: Primitives    →  Raw values (colors, sizes)
Layer 2: Semantic       →  Named by purpose (backgrounds, text, borders)
Layer 3: Component      →  Scoped to components (button bg, input border)
```

### Why 3 layers?

- **Primitives** are stable — they rarely change
- **Semantic** tokens map intent — swap a theme by remapping these
- **Component** tokens enable surgical overrides without side effects

### Semantic Tokens

```css
/* Backgrounds */
--color-bg-primary      /* Main app background */
--color-bg-secondary    /* Cards, panels */
--color-bg-tertiary     /* Nested surfaces */
--color-bg-elevated     /* Elevated elements */

/* Text */
--color-text-primary    /* Main text */
--color-text-secondary  /* Supporting text */
--color-text-code       /* Code/terminal text (green) */
--color-text-link       /* Links (cyan) */

/* State */
--color-state-success   /* Green */
--color-state-warning   /* Amber */
--color-state-error     /* Red */
--color-state-info      /* Cyan */

/* Actions */
--color-action-{brand,secondary,tertiary,danger}-{default,hover,active,text}
--color-action-{brand,secondary}-{bg,border}   /* Subtle tint + outline */

/* Accents (decorative, non-semantic) */
--color-accent-green / -cyan / -violet
```

Every foundation-namespaced token a core component references must be defined here. `token-coverage.test.ts` fails the test suite on an undefined `var(--color-…)`, `var(--font-…)`, and so on.

## Design-style tokens

Style tokens let a theme reach the parts of a component that colour alone cannot: gradients,
textures, glass blur, hard or soft shadows, border weight and decorative type. Their defaults are
no-ops, so the default, light and calm themes render exactly as before; a design-style preset
(Glass, Brutalism, Neumorphism…) is pure CSS that overrides them on a `[data-theme]` selector.

| Token | Default | Consumed by |
|-------|---------|-------------|
| `--gradient-surface` | `none` | Card, Modal, Dialog, Drawer, Popover, NavBar, Header, Sidebar, BottomNav, DataTable, secondary Button, Table/DataTable headers, PageShell/AppLayout header and sidebar |
| `--gradient-brand` | `none` | brand Button at rest (under the label) |
| `--gradient-brand-hover` | `none` | brand Button `:hover` (replaces `--gradient-brand`) |
| `--gradient-brand-active` | `none` | brand Button `:active` (replaces `--gradient-brand`) |
| `--gradient-accent` | `none` | active Tab indicator strip (never under text) |
| `--gradient-backdrop` | `none` | `body`, PageShell, AppLayout |
| `--texture-surface` | `none` | same surfaces as `--gradient-surface` (except table headers) |
| `--pattern-backdrop` | `none` | `body`, PageShell, AppLayout |
| `--surface-blur` | `none` | Modal, Dialog, Popover panels (`backdrop-filter`) |
| `--shadow-offset` | `0 0 0 0 transparent` | Button, Card, Modal, Dialog, Drawer, Popover |
| `--shadow-raised` | `0 0 0 0 transparent` | Button and Card, at rest and on hover |
| `--shadow-pressed` | `0 0 0 0 transparent` | Button `:active` |
| `--shadow-inset` | `0 0 0 0 transparent` | TextInput, Textarea, Select |
| `--border-width` | `1px` | borders of the components above plus Badge, Tabs, Table |
| `--border-width-strong` | `2px` | Tabs / NavBar active indicator |
| `--border-style` | `solid` | every border that uses `--border-width` |
| `--font-decorative` | `var(--font-display)` | Modal, Dialog, Drawer, Header and PageHeader titles |
| `--heading-transform` | `none` | the same titles (`text-transform`) |
| `--color-accent-1..4` | green, cyan, violet, amber accents | CommentThread depth markers (depth 1–3, then accent 4 for depth 4+) |

Background tokens are one or more **non-final background layers** — an image with optional
`position / size`, repeat and attachment, but no colour — because components append the surface
colour as the last layer (`background: var(--texture-surface), var(--gradient-surface),
var(--card-bg)`). Shadow tokens default to a transparent zero shadow so they can sit in a
`box-shadow` list next to the existing elevation and glow shadows.

```css
[data-theme="glass"] {
  --card-bg: #1a1733;
  --surface-blur: blur(16px) saturate(140%); /* Modal, Dialog, Popover only */
  --pattern-backdrop: radial-gradient(circle at 20% 20%, #7f5af0 0, transparent 40%) fixed;
}

[data-theme="brutalism"] {
  --border-width: 3px;
  --border-width-strong: 4px;
  --shadow-offset: 6px 6px 0 0 #000;
  --radius-md: 0;
  --radius-lg: 0;
}
```

A theme that changes `--font-display` on a subtree must redeclare
`--font-decorative: var(--font-display)` there too, because `var()` resolves where a token is
declared.

## Themes

The default `:root` palette is the neon dark theme; `data-theme="light"` remaps it for light
surfaces. Every theme redefines Layer 2 (semantic) and Layer 3 (component) tokens only —
primitives never change — so components pick up a theme with no prop changes.

### Calm preset

`@cyberdynecorp/svelte-ui-foundation/themes/calm.css` is an optional preset for products that
need a quiet, trustworthy look (finance, health). It ships two themes:

| Theme | Selector | Palette |
|-------|----------|---------|
| Calm | `[data-theme="calm"]` | sand backgrounds, stone text, sage brand, mist info/focus |
| Calm dark | `[data-theme="calm-dark"]` | deep stone backgrounds with the same hues lifted for dark |

Load it **after** the foundation styles, then set the attribute on `<html>` (or any subtree):

```svelte
<script>
  import "@cyberdynecorp/svelte-ui-foundation/styles";
  import "@cyberdynecorp/svelte-ui-foundation/themes/calm.css";
</script>
```

What the preset guarantees (enforced by `themes/presets.test.ts`):

- **Complete** — every Layer 2 and Layer 3 token of the default theme has a calm value (the
  theme-invariant `--video-*` tokens excepted), so no neon default can leak through. Adding a new
  semantic token without a calm value fails the build.
- **WCAG AA** — every declared text/background pairing is ≥ 4.5:1 and every meaningful UI
  pairing (focus rings, input and strong borders, accents) is ≥ 3:1, in both themes.
- **Calm motion** — `--transition-fast` 120ms, `--transition-default` 180ms and
  `--transition-slow` 200ms on `cubic-bezier(0.2, 0, 0, 1)`; `--transition-spring` is a plain
  180ms `ease-out` (no overshoot).
- **Quieter type and shape** — `--font-display` is Inter; radii are softer (cards 16px,
  inputs 10px); `--nav-height` is 64px; shadows are soft with no glow.

Pick the preset from the Storybook toolbar (Theme → Calm / Calm dark) to preview any component,
or see `Design Tokens/Themes`.

```svelte
  import "@cyberdynecorp/svelte-ui-foundation/styles";
  import "@cyberdynecorp/svelte-ui-foundation/themes/brutalism.css";

<!-- whole app: <html data-theme="brutalism">, or any subtree: -->
<section data-theme="brutalism">…</section>
```

Every preset carries the same guarantees as calm (enforced by `themes/presets.test.ts`): all
Layer 2 and Layer 3 tokens and every design-style token are defined, only foundation tokens are
set (never primitives or `--video-*`), the calm pairing list meets WCAG AA, and motion stays at
≤ 200ms with no overshoot. Reduced motion is handled by the global rule in `animations.css`.

Things to know:

- **Fonts are not loaded.** Each preset names its font families (e.g. Archivo Black, Fraunces,
  Orbitron, Playfair Display) with system fallbacks; the file header says which Google Fonts to
  load. Without them the fallbacks render.
- **Decorative layers are not contrast-checked.** Gradients, textures and patterns sit at low
  alpha over the checked flat colours; keep long text off busy backdrops.
- **Glass surfaces are opaque tints** so their contrast is verifiable; the glass look comes from
  the surface sheen, rim highlight, translucent borders and the aurora backdrop, not from a live
  blur. `--surface-blur` only reaches the floating Modal, Dialog and Popover panels: a
  `backdrop-filter` on a container would become the containing block of `position: fixed`
  descendants (dialogs, menus, toasts), so Card, Drawer, NavBar, Header and BottomNav never set it.
- **Brand gradients have state variants.** When `--gradient-brand` is opaque it hides the hover
  and active button colours, so set `--gradient-brand-hover` / `--gradient-brand-active` too
  (`presets.test.ts` requires distinct values and checks the label on every opaque stop).
- **Shape changes are global.** Swiss sets `--radius-pill: 0`; brutalism, memphis and maximalism
  thicken `--border-width`; art-deco uses `--border-style: double`; organic sets four-value
  `--radius-lg` / `--radius-xl`, so use those two only as a whole `border-radius` value.
- **Colour-only distinctions are weaker** in minimal (grey accents; links need underlines) and
  swiss (brand and danger are both red).
- Bento's generous gaps are layout: use a spacing-scale gap (e.g. `var(--space-6)`) in your grid.

Pick any preset from the Storybook toolbar (Theme menu) to preview real components, or see
`Design Tokens/Themes` → Style Switcher / Style Gallery.

### Theme preference (light / dark / system)

`@cyberdynecorp/svelte-ui-foundation/theme` is a framework-agnostic, SSR-safe helper that
resolves `system | <light> | <dark>`, applies it to `document.documentElement.dataset.theme`,
persists the choice to `localStorage` and, under `system`, follows
`prefers-color-scheme: dark` live. Storage failures (private mode, blocked site data) never
throw; they fall back to `system`.

```ts
import { createThemePreference } from "@cyberdynecorp/svelte-ui-foundation/theme";

const theme = createThemePreference({
  storageKey: "app.theme",
  themes: { light: "calm", dark: "calm-dark" },
});

theme.get(); // "system" | "calm" | "calm-dark" (stored preference)
theme.resolved(); // "calm" | "calm-dark" (applied theme)
theme.set("calm-dark");
const unsubscribe = theme.subscribe(({ preference, resolved }) => {}); // store contract
theme.destroy(); // stop following the OS
```

To avoid a flash of the wrong theme, set `data-theme` before first paint with the matching inline
script. Generate it once (same options as the helper) and paste it into `src/app.html`:

```ts
import { themeInitScript } from "@cyberdynecorp/svelte-ui-foundation/theme";

themeInitScript({ storageKey: "app.theme", themes: { light: "calm", dark: "calm-dark" } });
```

```html
<!-- src/app.html -->
<head>
  <script>
    (function(){var k="app.theme",l="calm",d="calm-dark",p=null;try{if(k)p=localStorage.getItem(k)}catch(e){}if(p!==l&&p!==d){try{p=matchMedia("(prefers-color-scheme: dark)").matches?d:l}catch(e){p=l}}document.documentElement.dataset.theme=p})();
  </script>
  %sveltekit.head%
</head>
```

A strict Content-Security-Policy needs a nonce or hash for this inline script.

`ThemeToggle` wraps the helper. It keeps its two-state light/dark switch by default; pass
`includeSystem` for a light / dark / system radio group and `themes` to map the modes to preset
names:

```svelte
<ThemeToggle includeSystem themes={{ light: "calm", dark: "calm-dark" }} persistKey="app.theme" />
```
